# F1 — inode reuse reproduced and corrected

Base: 2f29f1c3b4e3408cbebb0f3d122b1ec6894a1c1a. All product/test files remain unchanged.

Reproduction: `cargo test --locked -p pb-host --lib startup::tests::hs_t2 -- --nocapture` passes 9/9 with local /tmp (tmpfs). The identical command with `TMPDIR=/var/tmp` (ext4) fails exactly hs_t20/21/22, 6/9 pass. Logs: f1-tmpfs-tests.txt and f1-ext4-tests.txt. Prior GitHub runner shows the same failures: run 35131540290, Rust job 104913758022.

Root cause: ObjectIdentity in crates/pb-host/src/startup.rs compares type, uid, device and inode. The stale socket inode is not pinned across the first stat, failed connect, second stat, unlink and fresh bind. ext4 can reuse the freed inode immediately. hs_t20 observes equal old/new inodes; hs_t21/22 replace the pathname but receive READY instead of refusal because the identity tuple aliases. This is a product lifetime/identity issue exposed by the environment, not justification to select tmpfs or weaken tests.

Independent deterministic probe: `python3 .pipeline/resume/f1-inode-probe.py`. Observed tmpfs inodes 10251 -> 10252; ext4 unpinned 6410111 -> 6410111 (same identity); ext4 with O_PATH descriptor retained 6410111 -> 6410112. Linux descriptor semantics: https://man7.org/linux/man-pages/man2/open.2.html and https://man7.org/linux/man-pages/man2/unlink.2.html . Probe verifies mechanism, not a complete runtime patch.

Candidate minimal correction: obtain a no-follow O_PATH reference before accepting the first identity, use fstat on that descriptor, and retain it across recovery/fresh bind. Preserve fail-closed type/owner/path identity checks and existing outcomes. No patch applied yet: canonical originals are external/not-local and user requires demonstrated canonical conformity. Requested only the HOST_STARTUP/stale-socket normative excerpt or path; no general document reread needed. Residual pathname races beyond inode reuse require separate assessment if a patch is authorized by the source.

Next minimum action: obtain HOST_STARTUP normative excerpt, verify candidate against it, implement if compatible, run unchanged three tests on ext4 plus all startup tests. F2 Android investigation can proceed independently. Do not report F1 fixed and do not merge master.

## Correction after operator supplied the normative excerpt

The operator supplied C02 / Tech Sheet §4.3 / HS-004..012 and explicitly accepted O_PATH pinning only as a stronger stability proof. The scoped excerpt and SHA-256 are recorded in decisions/003-host-startup-excerpt.md and AUTHORITY.json; original authority remains unchanged.

crates/pb-host/src/startup.rs now obtains O_PATH|O_NOFOLLOW|O_CLOEXEC before the first no-follow stat, checks fstat identity against that pathname observation, and retains the descriptor through the fresh bind. Thus an unlinked old inode remains referenced while the replacement is inspected, preventing the observed identity alias. Existing type/owner/device/inode recheck before unlink, active-socket connect outcome, chmod/listen and refusal semantics remain. This addresses the demonstrated inode-reuse window, not a claim that all possible pathname races are eliminated.
